# uni-helper

## Overview

uni-helper makes tooling, templates, and documentation for the uni-app ecosystem. The interface should feel like a well-kept workshop: quiet surfaces, exact labels, and no decorative noise around the work.

The system is neutral-first. Zinc ink and off-white surfaces carry almost every screen. The brand green appears in marks, diagram shapes, accessible text accents, and one opt-in CTA. It does not fill the default primary button. This split keeps long documentation readable and lets the green stay recognisable as the brand.

Interfaces are compact but not cramped. Default controls are 36px high, body text is 16px, and the spacing scale starts at 2px so that dense tool panels can align to the same rhythm as marketing pages. Coarse-pointer devices raise interactive targets to 44px.

The writing is Chinese-first. English appears in package names, APIs, commands, and code. The interface never uses exclamation marks or marketing superlatives.

The source of truth is `tokens.json`. `tokens.css`, the integration files, the frontmatter above, and the Agent Skill assets are generated from it. Do not edit generated files by hand.

## Colors

The palette has four jobs: neutral structure, brand identity, status, and code.

- **Background and foreground (#ffffff / #09090b in light, #09090b / #fafafa in dark):** Body surfaces and text. The pair reaches 19.9:1 in light and 19.06:1 in dark.
- **Card and popover (#ffffff / #09090b in light, #141416 / #18181b in dark):** Raised surfaces. Dark surfaces are deliberately lighter than the page so cards do not disappear into it.
- **Primary (#18181b in light, #fafafa in dark):** The fill for the single main action on a screen. This is zinc ink, not brand green.
- **Primary foreground (#fafafa in light, #18181b in dark):** Text and icons on primary. The pair reaches 16.97:1 in both themes.
- **Secondary, muted, accent (#f4f4f5 in light, #27272a in dark):** Quiet fills for secondary buttons, code blocks, hover states, and selected rows. They share one value on purpose; the role is decided by the component.
- **Muted foreground (#6b6b74 in light, #a1a1aa in dark):** Secondary text. It reaches 5.28:1 on light background, 4.8:1 on light muted, and 7.76:1 on dark background.
- **Border (#e4e4e7 in light, #3f3f46 in dark):** Decorative one-pixel separators.
- **Border strong and input (#8f8f99 in light, #63636e in dark):** Control and input boundaries. They reach at least 3:1 so the control remains identifiable without relying on focus alone.
- **Ring (#18181b in light, #d4d4d8 in dark):** Keyboard focus. Never remove the focus ring.
- **Brand (#2b9939):** The uni-helper mark. White text on it reaches only 3.67:1, so use it for marks, borders, diagram fills, and display-size text. Do not set body copy in white on green.
- **Brand deep, mint, soft (#1c6325, #8acb9b, #a9d6b0):** Supporting greens for the three-shape mark, diagram grounds, and tints.
- **Brand text, link, brand CTA:** Theme-aware accessible greens. Light uses #1c6325; dark uses #8acb9b. `brand-text` reaches 7.34:1 on light and 10.51:1 on dark. `brand-cta` is opt-in; the default primary action stays ink.
- **Info, success, warning, error:** Status accents with separate light and dark values. They colour borders and icons. Message text stays foreground, so the reader never depends on hue alone.
- **Chart 1–6 and code tokens:** Data visualisation and syntax highlighting have their own semantic slots. They are not interchangeable with status colours.

The light and dark themes share token names. Set `data-theme="dark"` on the root. `.dark` is also supported for Nuxt UI compatibility. When neither is set, the system follows `prefers-color-scheme`; an explicit `data-theme` always wins.

## Typography

Geist carries every Latin interface and document size. Geist Mono carries code, key caps, and fixed-width values. Chinese falls back to Noto Sans SC, then PingFang SC or Microsoft YaHei, then the system CJK face. The system does not bundle a CJK font.

- **Display:** 36px / 1.1, 800, -0.025em. Fluid to 32–36px. Chinese uses 1.2 line height and zero tracking.
- **Heading 1:** 30px / 1.2, 600. Fluid to 28–30px. Chinese uses 1.3 line height and zero tracking.
- **Heading 2:** 24px / 1.3, 600, -0.02em. Chinese uses 1.35 line height and zero tracking.
- **Heading 3:** 20px / 1.4, 600. Chinese uses 1.5 line height.
- **Heading 4:** 18px / 1.4, 600. Chinese uses 1.5 line height.
- **Body:** 16px / 1.75, 400. Chinese uses 1.8. Keep the measure near 72 characters.
- **Small:** 14px / 20px, 400. Tables, captions, and secondary copy.
- **Nav:** 14px / 20px, 600. Navigation, button labels, and control labels.
- **Label:** 12px / 16px, 600. Badges and compact labels.
- **Field label:** 14px / 20px, 500. Form field labels.
- **Code:** 14px / 20px, 400, Geist Mono.
- **Kbd:** 10px / 1, 500, Geist Mono.

Use the `uh-type-*` classes instead of raw font declarations. They read the type tokens and apply the Chinese tracking and line-height overrides through `:lang(zh)`.

Do not set body text below 14px. The tight letter-spacing belongs to display and heading sizes only. Use `uh-nums` for tabular numbers in tables, versions, counters, and developer tool readouts.

## Layout

The spacing scale is built on a 4px step, with a 2px half-step for hairlines.

- 2px: divider inset and hairline gaps.
- 4px: icon-to-text gap.
- 8px: default inline gap.
- 12px: control padding.
- 16px: card padding and page gutter.
- 24px: card padding and block gap.
- 32px and 48px: section spacing.
- 64px to 96px: page bands and hero space.

Related controls share a gap. Separate groups with at least 24px. A card uses 24px inner padding. A page uses 16px gutters; the `uh-container` class caps at 1120px, narrow prose at 720px, and wide shells at 1440px.

Breakpoints are 640px, 768px, 1024px, and 1280px. Content sits in a single column unless it is a set of cards, a comparison, or a tool panel. Use `uh-grid` for auto-fit card grids and `uh-grid--2`, `--3`, `--4` for explicit columns from 768px up.

## Elevation & Depth

Borders carry most of the separation. Shadows are a hint that a surface is above another; they never decorate.

- **shadow-sm:** Controls, inputs, and small cards.
- **shadow:** Raised cards.
- **shadow-lg:** Dialogs and popovers.

Light and dark have separate shadow values; dark shadows are stronger so they remain visible on the near-black page. Use one shadow level per surface. A card with a border and `shadow-sm` is enough. Do not stack `shadow` on a card that already sits in a bordered container. Menus and dialogs use `shadow-lg` with a 1px strong border.

## Shapes

- **4px (sm):** Badges, key caps, and small controls.
- **6px (md):** Buttons, inputs, and menu items.
- **8px (lg):** Standard cards, popovers, alerts, and code blocks.
- **12px (xl):** Media cards, dialogs, and large containers.
- **9999px (full):** Pills, avatars, dots, and the switch track.

Keep one radius family per control group. A button, its input, and its menu item use 6px. A standard card and the alert inside it may use 8px. A card with a 16:9 media band may use 12px through `uh-card--media`.

## Motion & Micro-interaction

State changes use `--duration-fast` (150ms) and `--ease-standard`. Larger transitions use `--duration-slow` (300ms) and `--ease-out`. The hero CTA expands a circle from the dot across the whole pill; it does not rely on a fixed pixel radius that can miss wide labels.

Motion only animates `background-color`, `border-color`, `color`, `outline-color`, `box-shadow`, `opacity`, `transform`, and `clip-path`. Under `prefers-reduced-motion: reduce`, transitions drop to 1ms and skeleton/spinner animations stop. Focus rings appear immediately; they never animate.

## Voice & Content Strategy

- **Tone:** Direct, technical, and calm. State the action and the result. Never use exclamation marks, urgency, or praise.
- **Language:** Chinese first. Keep package names, APIs, file paths, and commands in code format. English UI text uses sentence case.
- **Terminology:** Say 包 for an npm package, 插件 for a Vite or uni-app plugin, 模板 for a starter, and 文档 for documentation. Use one word for one concept.
- **Button and action labels:** Start with a verb: 新建项目, 查看文档, 发布. Keep Chinese labels to two to six characters. Do not end a label with punctuation.
- **Errors:** State what failed and the next action. "The build failed: fix the type error before exporting." Do not blame the reader.
- **Empty states:** Say what belongs in the list and how to add it. Do not use jokes.
- **Numbers and units:** Put a space between a number and its unit in prose (16 px). Keep versions and paths unbroken.

## Accessibility

- Body text reaches 4.5:1 or better on background, card, and muted in both themes.
- Control boundaries, input borders, focus rings, and status icons reach at least 3:1.
- Every interactive element keeps a visible focus ring. Use a 2px outline with 2px offset; inputs keep both the border change and the outline.
- Do not remove the focus ring or replace it with a colour change. In forced-colors mode the ring maps to `Highlight`.
- Do not rely on colour alone for status. Pair the hue with a title, an icon, or text.
- Icon-only buttons need an `aria-label`. Decorative icons stay `aria-hidden="true"`.
- Use native controls where possible. Set `required` or `aria-required` on required fields; the asterisk is decorative.
- Coarse-pointer devices use 44px minimum interactive targets.
- `prefers-reduced-motion: reduce` stops decorative motion and loading loops.

## Components

The canonical markup and states live in `components/index.html`. Styles live in `components/components.css`. Token values live in `tokens.json` and the generated `tokens.css`.

### Actions

- **Button:** Variants default, secondary, outline, ghost, destructive, brand, link. Sizes sm, default, lg, icon. One default button per view. The brand variant is opt-in for a single brand moment; it is not the default primary action.
- **Link:** `uh-link` for inline navigation. Green by default, with an accessible hover.
- **InteractiveHoverButton:** `uh-ihb` is a hero pattern, not a base component. One per view. The label and icon stay constant; the fill expands from the dot. Keep the markup single-label so assistive technology does not hear it twice.

### Forms

- **Field:** `uh-field`, `uh-field__label`, `uh-field__hint`, `uh-field__error`. Wrap every input with a field.
- **Input, Select, Textarea:** 36px high, 1px strong border, 6px radius. Pair with a visible label or an `aria-label`.
- **Checkbox, Radio:** Native 16px controls tinted with primary. Use checkboxes for independent choices, radios for one choice, and a switch for an immediate setting.
- **Switch:** `uh-switch` with a visible track and a native checkbox for state.

### Feedback

- **Alert:** Default, info, warning, success, and danger. The title states the condition; the body states the action. Do not stack more than three on a page.
- **Toast:** Bottom-right region, one message per event. State the result, not a slogan.
- **Spinner, Skeleton:** Loading placeholders. Stop animation under reduced motion.
- **Empty state:** Say what belongs here and how to add it.

### Navigation

- **Tabs:** Arrow-key navigation, `aria-selected`, and hidden panels.
- **Breadcrumb, Pagination:** Use the native link and `aria-current` patterns.
- **Sidebar and TOC:** `uh-nav-item`, `uh-toc`. Use one current item per region.

### Content

- **Card:** One destination per card. A whole-card link has no second link inside it. Standard cards use 8px; media cards use `uh-card--media` at 12px.
- **Table:** Wrap in `uh-table-wrap`; right-align numeric columns with `uh-table__num`.
- **Prose:** `uh-prose` handles headings, lists, blockquotes, inline code, tables, and images for documentation.
- **Code block:** `uh-code-block` with an optional header and copy button. Syntax classes map to the code tokens.
- **Kbd:** One key per cap. Write a chord as separate caps.
- **Dialog:** Native `<dialog>` with a strong border, 12px radius, and overlay backdrop. Use `showModal()`.
- **Separator, Badge:** One job each. A badge is never a button.

### Layout

- **Stack, Row, Container, Grid:** `uh-stack`, `uh-row`, `uh-container`, `uh-grid`. Use these instead of page-local layout classes.

## Patterns

- **Hero CTA:** One `uh-ihb` in the hero, plus supporting secondary actions.
- **Command palette:** Compose a dialog, a search input, a result list, and keyboard hints. Do not reuse the base table as a result list.
- **Data table:** Compose `uh-table`, a toolbar, pagination, and an empty state. Keep numeric columns tabular.
- **Tree:** Compose `uh-nav-item` with disclosure buttons and `aria-expanded`. Do not fake tree semantics with nested links alone.
- **Forms:** Use `uh-field` for every control; put the primary action after the fields, and keep the error next to the field.

## Do's and Don'ts

- Do use `--primary` for the main action and `--brand` for identity.
- Don't fill the default primary button with brand green.
- Do use `--brand-text` or `--link` when you need accessible green text.
- Do keep body text at 16px and secondary text at 14px or larger.
- Don't use more than two font weights on one screen.
- Do use 6px radii for controls and 8px for standard cards; 12px is reserved for media cards and dialogs.
- Don't mix 6px and 8px on the same control group.
- Do keep one default button per view.
- Don't use a badge as a button.
- Do keep status text in `--foreground` and the hue on the border or icon.
- Don't use colour alone to carry status.
- Do keep the focus ring visible on every interactive element.
- Don't remove the focus ring or replace it with a colour change.
- Do keep the Chinese line-height and zero tracking from `uh-type-*`.
- Don't apply Latin negative tracking to Chinese headings.
- Do disable motion under `prefers-reduced-motion`.
- Don't animate layout properties.
